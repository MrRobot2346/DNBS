2. Core Concepts Explained

1. Frontend Only

The visual pages, interactive forms, cards, search bars, and previews that users interact with in their web browser.

2. Shared Demo State

A single in-memory JavaScript data store (NoticeStore) that connects student and administrator views inside the same browser session so you can see live interactions without a backend.

3. Universal Notice Form

One reusable modal used across all five categories. When opened from a category page, the category is fixed so administrators can focus directly on content.

4. Browser File Picker & Previews

Opens your device's native file dialog and creates instant client-side preview URLs (URL.createObjectURL). Previews do not mean files are uploaded to an external server.

5. Deadline-Based Sorting

Dynamic sorting prioritizing notices with upcoming deadlines (closest deadline first), followed by notices without deadlines (newest first), and passed deadlines (newest first).

6. Demo Database Viewer

A read-only tabular representation simulating the future SQLite table schema (id, title, category, deadline, etc.) for teammates to preview data structures.

7. Future Flask Backend

The upcoming Python/Flask server will receive requests, enforce strict server-side validation, authenticate administrator passwords, and save uploaded files to disk.

8. Real Synchronization

In the final app, multiple distinct computers and student phones will see changes because they query the centralized SQLite database over HTTP endpoints.
